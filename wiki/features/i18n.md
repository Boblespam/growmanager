# Multilingue (i18n) : FR / EN / DE / ES

**Pourquoi** : le recrutement des testeurs du test fermé Google Play (12 testeurs sur 14 jours, voir [[roadmap]], section Distribution Google Play) bloque parce que l'app n'existe qu'en français. Des testeurs anglophones, germanophones et hispanophones sont possibles.

**Statut** : étude faite et validée par Pik le 2026-10-23. Rien n'est lancé. Les décisions de la section 6 restent à trancher avant le Sprint 0. ADR associé en brouillon : [[architecture/decisions#ADR-010 : Multilingue i18n (brouillon 2026-10-23)|ADR-010]].

## 2. Architecture proposée

1. **Lib** : `i18next` + `react-i18next` (pluriels par langue, interpolation `{{count}}`, fallback). Les JSON des 4 langues sont **embarqués dans l'APK** (le mode autonome doit marcher hors ligne), ~100-150 Ko par langue.
2. **Langue = préférence de l'appareil** (`localStorage` clé `gm_lang`), pas en base. Fonctionne dans les deux modes, aucune migration. Détection de la langue du téléphone au premier lancement, modifiable dans Paramétrage.
3. **Source FR, fallback EN** (téléphone en italien → anglais). Clé manquante → FR, jamais de blanc.
4. **Namespaces par domaine** : `common`, `nav`, `culture`, `stock`, `graines`, `materiel`, `parametrage`, `croisement`, `recettes`, `sechage`, `stats`, `errors`, `listes`. Clés sémantiques (`culture.plants.empty`).
5. **Listes paramétrables : TRANCHÉ par Pik le 2026-10-23** (remplace la première décision du même jour, « aucune valeur traduite »).
   - **Valeurs libres** : créées **directement dans la langue choisie** au premier lancement (en mode autonome, la base est créée juste après le choix de la langue). Ensuite ce sont des données utilisateur, jamais retraduites : si la langue change plus tard, elles restent telles quelles. Coût : ~100 valeurs à traduire une fois (marques, références et termes techniques comme « LED Crescience », « 15µ », « Full Spectrum », LST restent identiques) + `seeds.ts` qui lit la langue. Le backend Python garde ses seeds FR (serveur de Pik).
   - **Valeurs verrouillées ou testées par le code** (catégories de matériel ADR-009, `Hash`, `Rosin`, `Hors service`, `Récolte`/`Hunt`/`Reproduction`, `Autre`...) : restent en **code français en base**, traduites **uniquement à l'affichage** (namespace `listes`, une vingtaine de valeurs). Elles ne doivent jamais être créées dans une autre langue.
   - Écarté : traduire à l'affichage toutes les valeurs (ex-option A), beaucoup plus de points de code à toucher (valeurs recopiées dans de nombreuses tables et affichées partout) et comportement incohérent dès qu'une valeur est renommée.
   - Point ouvert : verrouiller ou non les valeurs testées par le code mais non verrouillées aujourd'hui (un renommage casse déjà la logique, même en français).
6. **Erreurs = codes, pas phrases** : `LocalHttpError(404, 'culture.not_found', params)`, traduites côté front. Transition : si pas de code, affichage du `detail` brut. Backend Python : même schéma plus tard, PDF/CSV selon `Accept-Language`.
7. **Formats centralisés** : helper `fmt.date()` / `fmt.number()` / `fmt.month()` branché sur la langue active, remplace les 93 appels en dur. Unités métriques conservées (°C, g, L, €).
8. **Glossaire métier validé avant toute traduction** : beaucoup de termes sont déjà anglais et utilisés tels quels par les growers DE/ES (LST, SCROG, WPFF, rosin, curing, trim, AACT). À figer : LSO / sol vivant, réamendement, burping, TCO, défoliation, passage 12/12.

## 3. Fichiers et zones impactés

**Nouveau**
- `frontend/src/i18n/` : config, détection, `locales/{fr,en,de,es}/*.json`, helpers de format
- Sélecteur de langue **en premier** dans `ModeSetup` (avant le choix du mode) + dans Paramétrage
- Script de parité des clés entre les 4 langues, lancé en CI
- Pseudo-langue de test pour repérer les textes restés en dur

**Modifié**
- `main.tsx` (provider), `index.html` (`lang` dynamique), `Layout.tsx` (nav)
- 28 pages + 48 composants : textes → `t('...')`
- Tables de libellés : `ACTION_META`, statuts plante/culture, buts, types d'action
- `utils/calendarPdfExport.ts`, `CalendrierCulture.tsx`, `api/parametres.ts` (collator)
- `src/local/` : erreurs en codes, libellés `SETTINGS_DEFAULTS`, `seeds.ts` crée les valeurs libres des listes dans la langue choisie (valeurs verrouillées/testées toujours en code FR). Le portage du PDF étiquette QR en local (sprint B9) devra naître traduit.
- 22 `confirm()` / `alert()`

**Plus tard (mode serveur)**
- Backend Python : erreurs en codes, PDF étiquette stock + recettes, en-têtes CSV via `Accept-Language`

**Hors code**
- Play Console : fiches EN/DE/ES (titre, description courte 80 car., description longue, captures traduites), politique de confidentialité traduite
- Android : corriger `app_name`
- Wiki : ADR-010 définitif, règle dans [[frontend/conventions]], [[roadmap]]

**Impact durable** : toute nouvelle chaîne devra avoir sa clé dans les 4 langues (bloqué en CI sinon). Les features prendront un peu plus de temps.

## 4. Plan par sprints

Le coût est dans l'**extraction** des textes. Une fois une page extraite, ajouter DE ou ES revient à remplir du JSON. On extrait donc en visant l'EN d'abord.

| Sprint | Contenu | Livrable |
|---|---|---|
| **I0 : Socle** | ADR-010, glossaire, i18next, détection, sélecteur (ModeSetup + Paramétrage), helpers format, script de parité, pseudo-langue | Infra prête, rien de visible |
| **I1 : Parcours testeur** | Nav, ModeSetup, Dashboard, Culture + composants (PlantesTab, ActionModal, ArrosageModal, CalendrierCulture, NouvelleCultureModal), Graines, erreurs du mode local, statuts et actions | **Version EN testable sur le parcours principal, de quoi lancer le recrutement** |
| **I2 : Cœur métier** | Stock, Séchage/Curing, Matériel, Espaces, Recettes, Sol vivant, Plan culture, Préparation substrat, dictionnaire des listes paramétrables | Usage courant 100 % EN |
| **I3 : Le reste** | Parametrage, Croisement, Statistiques, Classement, Comparaison, Consommation, Vapo, Calendrier global + PDF | 100 % de l'UI extraite |
| **I4 : Langues & store** | Traductions DE/ES + relecture native, contrôle des débordements (allemand ~30 % plus long), fiches Play, backend Python | FR / EN / DE / ES complets |

**Méthode** : un commit par page ou groupe de composants, testé sur APK. Pas de nouvelle feature sur une page en cours de migration.

## 5. Risques

- **Régression silencieuse** : traduire une valeur testée par égalité. Protection : option A + règle « traduction à l'affichage uniquement ».
- **UI partiellement FR pendant la transition** : acceptable pour des testeurs prévenus, fallback EN.
- **Qualité DE/ES** : générées par Claude, relecture par au moins un natif par langue (les testeurs peuvent jouer ce rôle).
- **Mise en page mobile** : textes allemands longs, passe visuelle page par page.
